## 1. 产品概述

### 1.1 产品定位

一款面向年轻用户的微信小程序，解决朋友聚餐前"吃什么"的决策难题。用户可以像在饭店一样浏览菜谱、选菜、生成点菜单，并通过微信分享给好友协作点菜。

### 1.2 目标用户

- 经常与朋友聚餐、点外卖的年轻人
- 不想每次为"吃什么"争论的群体
- 享受仪式感点菜体验的用户

### 1.3 核心价值

- **决策效率**：替代"随便"、"都行"的无效沟通，快速达成共识
- **协作体验**：多人同时选菜，各选各的，最终汇总
- **仪式感**：模拟饭店菜单的浏览和点菜体验，带标价和菜品图片

## 2. 功能需求

### 2.1 功能模块总览

| 模块 | 优先级 | 状态 | 说明 |
|------|--------|------|------|
| 浏览菜谱 | P0 | 已完成 | 按分类浏览，支持搜索和当季推荐 |
| 菜品详情 | P0 | 已完成 | 查看菜品图片、描述、价格、食材信息 |
| 选菜车 | P0 | 已完成 | 本地暂存选中的菜品，支持增删 |
| 协作点菜 | P0 | 已完成 | 生成点菜单，分享给好友追加菜品 |
| 菜品图片管理 | P1 | 开发中 | 爬虫采集 + 云存储上传 + 自动关联 |
| 数据库初始化 | P1 | 已完成 | 56道示例菜品数据的初始化导入 |

### 2.2 首页 — 浏览菜谱

**用户故事**：作为用户，我想按分类浏览菜品，找到我想吃的菜。

**功能描述**：

- **当季推荐**：根据当前月份自动识别季节（春/夏/秋/冬），展示当季推荐菜品
- **分类筛选**：支持 6 个分类的 Tab 切换
  - 全部 / 凉菜 / 热菜 / 汤羹 / 主食 / 甜品小吃 / 饮品
- **菜品卡片**：展示菜品图片、名称、价格、简介
- **加入菜单**：点击"加入"按钮将菜品添加到选菜车
- **购物车角标**：底部 Tab 显示已选菜品数量

**交互流程**：

```
进入首页 → 看到当季推荐 + 全部菜品列表
  → 点击分类 Tab 筛选
  → 点击菜品卡片进入详情页
  → 点击"加入"按钮添加到选菜车
```

### 2.3 菜品详情页

**用户故事**：作为用户，我想查看菜品的详细信息再决定是否选择。

**功能描述**：

- 展示菜品大图
- 显示菜品名称、价格、详细描述
- 显示食材列表、烹饪时间、难度、辣度
- 显示标签（如：川菜、家常、快手菜）
- "加入/移除菜单"按钮，状态与选菜车同步
- 支持分享单道菜品给好友

### 2.4 选菜车 / 我的菜单

**用户故事**：作为用户，我想查看已选的菜品、调整选择、生成点菜单并分享。

**功能描述**：

- **菜品列表**：展示已选菜品的图片、名称、单价
- **总价计算**：底部显示合计金额（纯展示，无支付）
- **删除菜品**：左滑或点击删除单道菜品
- **清空菜单**：一键清空所有已选菜品（需二次确认）
- **生成点菜单**：调用后端创建订单，生成 8 位分享码
- **分享功能**：通过微信转发给好友，好友打开即可查看并追加菜品

**交互流程**：

```
进入菜单页 → 查看已选菜品和总价
  → 删除不需要的菜品
  → 点击"生成点菜单"
  → 分享给微信好友
```

### 2.5 分享页 — 协作点菜

**用户故事**：作为被分享者，我想查看好友选的菜，并追加自己想吃的。

**功能描述**：

- **查看点菜单**：展示创建者已选的所有菜品和总价
- **追加菜品**：点击"加菜"按钮，弹出选菜面板
  - 选菜面板支持分类筛选
  - 选择后直接追加到点菜单
- **再次分享**：支持将更新后的点菜单转发给更多人
- **状态展示**：显示每道菜是谁添加的

**交互流程**：

```
点击微信分享链接 → 进入分享页 → 看到已选菜品列表
  → 点击"加菜" → 弹出选菜面板 → 按分类选择 → 确认追加
  → 点击"分享" → 转发给其他好友继续点菜
```

### 2.6 图片管理工具

**用户故事**：作为管理员，我想为菜品配置真实图片，提升浏览体验。

**功能描述**：

- **图片采集**（Python 脚本）：通过 Pexels API 按关键词批量下载菜品图片
- **图片上传**（小程序工具页）：支持从相册选择图片上传到微信云存储
- **自动关联**（云函数）：将云存储中的图片与数据库菜品记录自动匹配
- **手动关联**（云函数）：支持手动指定文件名到菜品的映射关系

## 3. 数据模型

### 3.1 菜品 (dishes)

| 字段 | 类型 | 说明 |
|------|------|------|
| _id | string | 云数据库自动生成 |
| name | string | 菜品名称（如"番茄炒蛋"） |
| category | string | 分类：cold_dish / hot_dish / soup / staple / dessert / drink |
| price | number | 价格（元） |
| image_url | string | 图片地址（云存储 fileID 或 URL） |
| description | string | 菜品描述 |
| season_tag | string | 当季标签：spring / summer / autumn / winter（可为空） |
| ingredients | array | 食材列表 |
| cooking_time | number | 烹饪时间（分钟） |
| difficulty | string | 难度：easy / medium / hard |
| spiciness | number | 辣度：0-3 |
| tags | array | 标签（如：川菜、家常、快手菜） |

### 3.2 点菜单 (orders)

| 字段 | 类型 | 说明 |
|------|------|------|
| _id | string | 云数据库自动生成 |
| share_code | string | 8 位分享码（唯一） |
| creator_openid | string | 创建者标识 |
| status | string | 状态：active / closed |
| items | array | 菜品列表（嵌套文档） |
| total_price | number | 总价 |
| created_at | date | 创建时间 |
| updated_at | date | 更新时间 |

### 3.3 订单项 (order_items，嵌套在 orders.items 中)

| 字段 | 类型 | 说明 |
|------|------|------|
| dish_id | string | 关联菜品 ID |
| dish_name | string | 菜品名称（冗余存储） |
| dish_price | number | 菜品价格（冗余存储） |
| dish_image | string | 菜品图片（冗余存储） |
| added_by_openid | string | 添加者标识 |

## 4. 菜品分类与数据

### 4.1 分类体系

| Key | 名称 | 菜品数量 | 价格区间 |
|-----|------|----------|----------|
| cold_dish | 凉菜 | 8 | 12-28 元 |
| hot_dish | 热菜 | 14 | 12-48 元 |
| soup | 汤羹 | 8 | 10-32 元 |
| staple | 主食 | 10 | 3-25 元 |
| dessert | 甜品小吃 | 8 | 8-18 元 |
| drink | 饮品 | 8 | 6-15 元 |

**合计**：56 道菜品

### 4.2 当季推荐逻辑

根据当前月份自动映射季节：

| 月份 | 季节 |
|------|------|
| 3-5 月 | spring（春） |
| 6-8 月 | summer（夏） |
| 9-11 月 | autumn（秋） |
| 12-2 月 | winter（冬） |

筛选 `season_tag` 与当前季节匹配的菜品展示在推荐区。

## 6. 用户标识方案

当前使用本地生成的伪 openid：

```javascript
openid = 'user_' + Date.now() + '_' + Math.random().toString(36).substr(2, 6)
```

存储在 `wx.setStorageSync('openid')` 中，用于标识"是谁添加了这道菜"。

> **注意**：V1 阶段不接入微信登录，使用本地生成标识即可满足协作点菜需求。

## 8. 非功能需求

### 8.1 性能

- 首页加载时间 < 2 秒
- 菜品列表分批加载（每批 20 条）
- 图片使用压缩尺寸（约 400px 宽）

### 8.2 兼容性

- 基础库版本 >= 2.2.3（云开发要求）
- 支持 iOS 和 Android

### 8.3 数据安全

- 云函数通过 `cloud.getWXContext().OPENID` 获取用户标识
- 点菜单状态支持 active / closed
- 无支付功能，仅展示价格

## 9. 已知限制与后续规划

### 9.1 当前限制

- 用户标识为本地生成伪 ID，同一用户换设备后身份丢失
- 菜品数据为预设的 56 道菜，暂不支持用户自定义
- 无用户登录体系，不支持历史记录

### 9.2 V2 规划

| 功能 | 优先级 | 说明 |
|------|--------|------|
| 用户往期点菜记录 | P1 | 基于 openid 保存历史菜单 |
| 菜品评价 / 点赞 | P2 | 用户可对菜品评分 |
| 菜单收藏 | P2 | 收藏常用菜单组合 |
| 自定义菜品 | P2 | 用户可添加菜谱中没有的菜 |
| 更丰富的菜谱数据 | P1 | 扩展到 100+ 道菜 |
| 菜品搜索增强 | P2 | 支持按食材、标签搜索 |
